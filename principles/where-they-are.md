# Where they are (user stage)

**Memory hook:** day 1 and day 100 need different screens.

## The idea
Not every user is at the same point. Someone who just signed up, someone
building a habit, and someone who uses the app every day want different
things from the same screen. Showing everyone the same generic screen
fails all three: it overwhelms the newcomer and slows down the regular.
Shape what's inside the screen to the user's stage.

## Why it works
A newcomer has no context yet, so every extra option is noise; they need
one clear first step. A returning user has a routine and wants today's
task right away. A heavy user already knows the basics and wants details,
progress and shortcuts. Content that matches the stage feels like the app
understands them; content that doesn't feels like clutter or like
starting over every time.

## Before / after
- **Before:** every user opens the same home screen: a welcome message,
  a tour, a long catalog, and their own data somewhere below.
- **After:**
  - **New user:** a short welcome, one clear first step (set a goal,
    add the first item), and a few easy things to explore.
  - **Returning user:** today's task or the next item first, with the
    key details (time, amount, what's due).
  - **Heavy user:** their stats and progress at the top, then their
    plan, then tailored suggestions.

## Where it applies
- **Home screens and dashboards:** onboarding content for newcomers,
  the next task for regulars, stats for heavy users.
- **Empty vs filled states:** an empty list explains how to add the
  first item; a full one gets search, sorting and summaries.
- **Tips and help:** show hints the first few times, then stop.
- **Messages:** greet a newcomer differently from someone with a streak.

## Do
- Define the stages for your app (for example: first use, building a
  habit, regular) and decide what each one needs most.
- Change the content inside sections; keep the main structure and
  navigation in the same place for everyone.
- Let users reach everything from every stage; adapting means ordering
  and emphasis, not hiding features.

## Don't
- Move buttons and sections around as the user progresses; it breaks the
  habits regulars rely on.
- Keep showing onboarding content to someone who uses the app daily.

## Guardrail
Personalization uses only data the user knowingly gave, and they can see
why something is shown. Sensitive data (health, money, location) needs
clear consent before it shapes the screen. The user can always reset or
turn off personal suggestions.

# Head start (goal gradient)

**Memory hook:** zero feels like standing still.

## The idea
People speed up as they get closer to a finish line. A progress indicator
at 0% says "you haven't started and there's a lot ahead", which is
deflating even when the actual work is small. You choose where the
starting line is: count what the user has already done, so they start
with momentum.

## Why it works
In a car wash study, one group got a card with 8 empty stamps; the other
got 10 stamps with 2 already filled. Same 8 washes needed, but the
head-start group completed the card at nearly double the rate.

## Before / after
- **Before:** an onboarding checklist at 0%, five empty steps.
- **After:** the same checklist at 20%, step 1 already checked, because
  creating the account is counted as step 1 instead of a separate event.
  The user did no extra work; the framing changed.
- **Real-world example:** LinkedIn shows a profile strength meter from the
  moment you sign up, and it's never at zero.

## Where it applies
- **Profiles:** completeness starts above zero by counting what's already filled in.
- **Checklists and schedules:** "2 of 5 done" counts steps already completed,
  even ones done outside the app.
- **Multi-step flows:** the step the user just finished counts as step 1.
- **Goals and streaks:** show distance to the next milestone, not just the total.
- **Imports:** after importing existing data, show how much is already set up.

## Do
- Show where the user is and how close the end is.
- Find something real the user has already done and count it.

## Don't
- Start any progress indicator at zero when something real is already done.
- Show a long list of remaining steps with nothing marked as done.

## Guardrail
Progress must be real. Count genuine steps (including reframing a step
the user truly completed); never invent completed ones.
Note: the source video says even artificial progress works.
This repo deliberately allows only real progress.

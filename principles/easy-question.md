# Easy question (decision ease)

**Memory hook:** every screen asks a question; make it an easy one.

## The idea
Every screen silently asks the user something. A hard question
("Is this worth $19 a month, forever?") gets the easiest answer: "later",
which usually means never. An easy question ("Can I try it for free?")
gets a fast yes. The offer can stay exactly the same; what changes is the
question the screen puts in the user's head. Before designing, name that
question, then reshape the screen until it's one the user can answer
quickly.

## Why it works
The less mental work a decision needs, the more likely people are to make
it. A decision with many unknowns feels like homework, and homework gets
postponed. Every "what if" the screen leaves open (how much will it really
cost, what happens next, how long will it take) adds to the work.
(The video names this "evaluative ease"; treat the label as an
illustration, the idea as the point.)

## Before / after
- **Before:** a subscription screen with a feature list, the monthly
  price and "Subscribe". The user has to judge whether three bullets are
  worth a recurring payment, before having tried anything.
- **After:** the same price and trial, but the screen explains how the
  free trial works, step by step. The question becomes "can I try this?"
  and the answer is obviously yes.
- **Before:** three options, each with a price range. The user mentally
  assumes the high end of every range and juggles three uncertain numbers.
- **After:** one clear price per option. Comparing takes seconds.
- **Before:** a list of options, and the user still hasn't confirmed what
  they're choosing for.
- **After:** the part the user already decided (the destination, the
  item, the date) is shown first, so the only question left is "which one?"
- **Before:** each filter on its own page, to keep things looking
  simple. The user picks one value without seeing the others, and only
  learns the result at the end.
- **After:** all filters together, with the result count updating as
  they change. More is on screen, but the decision is easier.
  Looking simpler is not the same as being easier to decide.

## Where it applies
- **Paywalls and upgrades:** explain how the trial or plan works instead
  of asking the user to judge its worth from a list.
- **Prices and amounts:** one number instead of a range, whenever you can
  truly commit to it.
- **Choices between options:** put the deciding facts (time, effort,
  convenience) next to the cost, so the choice isn't price alone.
- **Multi-step flows:** confirm the small, already-made decisions first;
  leave one small decision for the end.
- **Any screen with a main action:** before building, write down the
  question the screen asks, and check it can be answered in seconds.

## Do
- Name the question each screen asks, and make it the easiest honest one.
- Remove unknowns: show what happens next, what it costs, how long it takes.
- Show the user's earlier decisions back to them before the next one.

## Don't
- Make the user evaluate several uncertain things at once.
- Split connected decisions across screens to make each one look simpler.
- Show a range when you actually know the number.

## Guardrail
The easy question must lead to the true answer. Show one number only when
the price is genuinely fixed; if it can really change, say so clearly
rather than hiding the uncertainty until later. Making a decision easier
never means hiding what the user is agreeing to (see show-the-catch.md).
